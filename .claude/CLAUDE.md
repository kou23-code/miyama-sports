# CLAUDE.md（絶対ルール）

本プロジェクトで作業する際は、以下のルールを必ず遵守すること。

## 1. 言語

- 作業と説明はすべて日本語で行うこと。

## 2. プライバシー保護（カモフラージュ）

- 本番用プロジェクトのため、クラブとして公開している情報（クラブ名・所在地・代表電話番号・受付時間）は `js/default-config.js` と各HTMLに記載してよい。
- 上記以外の実在の施設名・団体名・公的機関名・個人名・個人の住所・電話番号・メールアドレスは、コード・テスト・コミット履歴・仕様書に絶対に含めず、架空のダミー情報を使用すること（テストデータも架空の値とする）。
- 公開してはならない値（通知先メールアドレス等）は、`.gitignore` 対象の `config.js` や GAS のスクリプトプロパティなど、リポジトリ外に置くこと。

## 3. Git運用

- `main` ブランチの直接編集は禁止（今回の初期構築を除く）。
- 機能・修正ごとに `feat-...` や `fix-...` ブランチを切ること。
- 日本語で小さくこまめにコミットし、実装とリファクタリングのコミットは分けること。
- `rebase` は禁止し、マージは必ず `git merge --no-ff` を使用すること。
- フォルダ名・ファイル名はすべて半角英数字とハイフンのみにすること。

## 4. コード品質と仕様管理

- 1つの関数は10行以下とすること。
- `const` を基本とし、`let` や `var` による再代入は行わないこと。
- 副作用のない純粋関数（Pure Function）で実装すること。
- 機能追加・修正時は必ず `SPEC.md` を最新状態に更新すること。

## 5. 実践ノウハウ

- ローカル（`file://`）でのリンク切れを防ぐため、ページ間リンクはフォルダ止めではなく、必ず `index.html` 等の末尾 `.html` まで明記すること。
- 実装中の確認は高速な Node.js 標準テストランナーによる単体テストのみを実行し、ヘッドレスChrome等による画面E2Eテストはマージ直前に変更箇所のみ1回だけ実行すること。
- OneDrive 配下で権限エラーが出る場合は、PowerShell（UTF-8）経由でファイル操作すること。
- GitHub Pages 等で公開可能なサーバーレス構成とし、サーバー上に個人情報を保持しないこと。
